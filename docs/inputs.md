# Input conventions

## Hamiltonian

`load_fcidump(path)` accepts a standard **real RHF spatial-orbital FCIDUMP**,
with uppercase `NORB`, `NELEC`, `MS2` fields and an `&END` or `/` terminator.
`NORB` counts spatial orbitals, while `CudaHamiltonian.n_orb` counts spin
orbitals. Use E-format real numbers, valid integral indices, a nonnegative
`MS2`, and an explicit core-energy `0 0 0 0` record. UHF block formats, complex
integrals, and spinor Hamiltonians are not accepted by this reader.

Spin orbitals are interleaved: `0α, 0β, 1α, 1β, ...`. Determinant phases use
creation operators in ascending order of these indices. Transform coefficients
and integrals together when importing a wavefunction from another convention.

Frozen-core contributions must already be folded into the one-electron
integrals and core energy. The reference energy and target diagonals must share
this energy offset. QiankunPT does not freeze orbitals, change the active space,
apply relativistic corrections, or convert a density-fitted Hamiltonian.

`load_fcidump()` returns antisymmetrized excitation tables:
single offsets/targets/spectator coefficients; double offsets/two-target
indices/values sorted by magnitude within each occupied pair; one-body and
symmetric pair diagonal tables. `save_tables()` and `load_tables()` preserve
these arrays in a non-pickle `.npz` file. They validate offsets, sizes, indices,
diagonal symmetry and the sorted-list invariant before CUDA use.

The standalone CPU reader in `_native/integrals.cpp` stores spatial integrals
once using their eightfold symmetry and directly builds these tables. Equal
magnitudes are ordered by target indices for deterministic output. With a
previously exported `.npz`, `load_tables()` reads the arrays directly; GPU
evaluation then uses the bundled CUDA kernels.

Dense excitation tables can require substantial CPU and GPU memory. Each GPU
retains its own Hamiltonian tables and reference.
Generate and cache them once when appropriate; do not infer capacity solely
from the number of orbitals.

## Reference wavefunction

```python
import numpy as np
from qiankunpt import Reference

reference = Reference(
    keys=np.array([[9]], dtype=np.uint64),
    coefficients=np.array([1.0], dtype=np.complex128),
    energy=0.0,
    n_spin_orbitals=4,
)
reference.save("reference.npz")
```

This reference is the `|0α 1β>` determinant in the two-site Hubbard example
generated by `qiankunpt make-example example-output`; its Rayleigh energy is 0 Ha.

- `keys` has shape `(N, ceil(n_spin_orbitals/64))`, with the low word first.
  Bit `p` indicates occupation of spin orbital `p`. `uint64` and signed `int64`
  are bit containers; an occupied bit 63 is valid.
- `coefficients` has shape `(N,)`, in exactly the same row order. Real and
  complex coefficients are accepted. The norm is computed explicitly, so
  coefficients need not have unit norm. Zero rows and duplicate determinants
  are rejected by the public `Reference` interface.
- `energy` is the Rayleigh energy of these coefficients **within this finite
  support** using the same Hamiltonian. It is neither a full-network VMC energy
  nor an independently extrapolated CI energy. The evaluator uses the supplied
  energy; it does not recompute or certify it.
- A valid electron-number/spin sector, orbital identity, reference quality and
  scientific interpretation remain the caller's responsibility. In particular,
  the external-only API does not test whether the reference solves CI.

Retain file hashes and orbital/integral provenance with scientific results.
